# Google Play Data Safety · ответы для сверки

Форма относится к пакету `app.butone.vpn` и ко всем распространяемым через Google Play вариантам этого пакета. Сверять ответы с финальным подписанным AAB и фактическими настройками AdMob. Установка рекламы меняет декларацию даже при отсутствии регистрации и собственной аналитики.

## Рекламный SDK

| Данные для проверки | Сбор и передача | Цель |
|---|---|---|
| Примерное местоположение | IP-адрес может использоваться Google для определения общей географии. | Реклама, измерение, предотвращение мошенничества. |
| Действия в приложении | Google SDK получает события запуска, нажатия и просмотры видео. | Реклама, измерение, предотвращение мошенничества. |
| Диагностика и производительность | Google SDK может получать сведения о запуске и зависаниях. Карточки «Диагностика», «Журналы сбоев» и «Другие данные производительности» сверять с документацией конкретной версии SDK и зависимостей. | Реклама, измерение, предотвращение мошенничества. |
| Идентификаторы устройства или другие идентификаторы | Google SDK может использовать Advertising ID, App Set ID и другие идентификаторы. Удаление разрешения AD_ID отключает рекламный идентификатор, но не отменяет необходимость проверки прочих идентификаторов. | Реклама, измерение, предотвращение мошенничества. |
| Выбор настроек рекламы | Отдельно сверить передачу данных формой UMP и включённые сообщения для каждого региона. | Управление выбором пользователя и соблюдение требований. |

Google указывает автоматический сбор и передачу для перечисленных категорий Google Mobile Ads и передачу по TLS. Перед подачей проверьте принятый SDK, объединённый манифест, параметры персонализации, согласие в разных регионах и дополнительные адаптеры. «Сбор по выбору» выбирайте только если пользователь может пользоваться приложением и полностью отказаться от соответствующего сбора. Если отказ отключает персонализацию, а часть сведений всё равно уходит при неперсонализированной рекламе или обновлении согласия, опциональность нужно оценивать по каждому типу данных. Рекламное профилирование нельзя считать кратковременной обработкой. [Раскрытие данных Google Mobile Ads SDK](https://developers.google.com/admob/android/privacy/play-data-disclosure) · [Форма Data Safety](https://support.google.com/googleplay/android-developer/answer/10787469) · [Настройка UMP](https://developers.google.com/admob/android/privacy)

## VPN, сетевые проверки и отчёты

| Поток данных | Как проверить и заполнить |
|---|---|
| Пользовательский трафик через VPN | Установить, какие данные доступны оператору каждого выбранного сервера. Как минимум проверить IP-адрес, сетевые назначения и содержимое запросов без прикладного шифрования. Рассмотреть категории «История просмотра веб-страниц», «Примерное местоположение» и иные применимые категории. Шифрование до сервера отвечает требованию VpnService, но само по себе не даёт исключения для сквозного шифрования в Data Safety, если данные читаемы посредником. |
| Операторы и хранение | Подтвердить поставщиков, их назначение и обработку клиентов. Для независимых операторов из публичного списка без подтверждения не заявлять нулевые логи, обработку только в памяти, окончательное удаление у оператора или исключение для поставщика услуг. Если сведения для точного раскрытия недоступны, проверить замену источников на контролируемые или договорные. |
| Списки серверов и проверки связи | Отдельно учесть сетевые метаданные, передаваемые источникам профилей, DNS-службам и тестовым адресам. Проверить каждый используемый маршрут и протокол. Проверочные запросы к сервисам не подтверждают полноценную работу всех их функций. |
| Локальный журнал | Записи, которые остаются на устройстве, не считаются сбором в Data Safety. Убедиться, что ни рекламные SDK, ни другой компонент не отправляет их сам. Убрать из экспортируемого отчёта пользовательские сетевые назначения и секреты, которые могут остаться в необработанных журналах ядра или старых журнальных записях. |
| Отчёт по явному действию | Проверить содержимое отчёта, экран предупреждения, пользовательский выбор получателя и правила поддержки. Для добровольной передачи, которую пользователь разумно ожидает, у Google есть исключение из категории sharing. Если итоговый релиз сам отправляет отчёт или использует библиотеку для доставки, заново оценить сбор и передачу. |
| Удаление | У приложения нет аккаунтов, поэтому путь удаления аккаунта не заявляется. Локальные данные удаляются очисткой хранилища, копии отчётов — пользователем, обращения в поддержку — по политике разработчика. Механизмы удаления у Google и сетевых операторов проверяются отдельно. |
| Шифрование всех собираемых данных | «Да» только после проверки всех каналов для всех заявленных данных. Проверить рекламные SDK, обновления списков, запросы диагностики и транспорт до VPN-сервера. |
